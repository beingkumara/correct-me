Correct Me

Upload a photo of handwritten math working. Correct Me reads it into lines you can fix, then finds the first line where the reasoning broke and asks a hint question, without ever giving the answer.

Three piecesThe model judges; your code decides what the student sees.

The page

public/: plain HTML, CSS and JS. Shrinks the photo, shows editable lines and the teacher's marks, keeps the session in memory.

The server

server/index.js: Express. Holds the Groq key, serves the page, and has two routes: /api/read and /api/check.

Your rules, in code

server/rules.js, leakGuard.js, validate.js: decide unsure, stop at the first wrong line, and keep the answer out of every hint.

One action: pressing CheckYour current lines go out; ticks, one red cross, and a hint come back.

Reference route: three stopsA reference to follow on your own. Open each file and search for the name in code.

  1. The button sends what's on the page now

    public/js/app.js → search checkCurrentLines

    It sends the current text of every line, plus the "?" lines you confirmed without editing (doubtfulLines in public/js/state.js). That's why Check again judges your edited working, not the original photo.

  2. The model judges; your code decides

    server/check.js → checkLines, then server/rules.js → calibrate and applyRules

    The checker returns a status, confidence and any alternative reading for each line. calibrate turns a confirmed misread, a low-confidence verdict, or "right under another reading" into unsure. The leak guard swaps out any hint that contains the answer, and applyRules stops at the first wrong line.

  3. The page draws the teacher's marks

    public/js/render.js → renderAside and renderNote

    Ticks, the red cross, the amber "?", the handwritten note and hint, "not checked", and the result line. All text goes in through textContent, so nothing from the model can run as code.

A practice to reuse

Check the raw AI output on a case you planted, and put the decision in code.

What happened: the prompt asked the checker to say "unsure" when it wasn't sure. On y = sin x² → dy/dx = 2 sin x cos x, a line that is right if you read it as (sin x)², it said "wrong" with 0.96 confidence. Asking it to write out any alternative reading surfaced (sin x)², so the rule "wrong but right under another reading → unsure" now lives in calibrate.

Evidence: npm run reality-check -- --lines samples/lines/ambiguous-sin-x-squared.txt prints the raw reply next to what the student sees; the test "sin x² read as (sin x)²…" in test/rules.test.js keeps the rule in place.

On your next project: when a model's answer drives what users see, keep a small set of inputs where you know the right answer, print the raw output beside the final result, and move any rule you can't trust the model to follow into tested code.
